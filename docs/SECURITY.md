# 安全边界

## 加密格式

aulycZip 创建 WinZip AES-256 AE-2 ZIP。该格式为了兼容性固定使用：

- PBKDF2-HMAC-SHA1，1,000 次迭代
- AES-256 CTR 内容加密
- HMAC-SHA1 截断认证码
- 每个文件独立的随机盐

这里的 SHA-1 仅用于 WinZip AES 协议规定的 HMAC/KDF，不用于自定义签名或普通内容摘要。AES 和 HMAC 由 macOS 系统 CommonCrypto 实现，没有自行发明加密算法。

## 文件名可见

WinZip AES 加密文件内容，不隐藏 ZIP 中的文件名和目录名。任何能打开中央目录的工具都可能列出这些名称。若名称本身敏感，应先把内容封装为单个中间归档，再加密这个归档文件。

## 解压防护

解压前会：

- 拒绝绝对路径、`..`、空路径组件和 Windows 盘符路径
- 按目标卷的大小写语义拒绝同名碰撞，并限制 UTF-8 路径和单组件长度
- 在写出明文前校验所有 AES 文件的密码验证值和认证码
- 限制最多 100,000 个条目
- 同时限制声明值与实际值：单条目流式输出不超过其声明大小和 20 GiB 全局单条目上限，总输出不超过 20 GiB
- 在 staging 前检查目标卷可用空间，并默认保留 512 MiB 系统余量
- 拒绝多卷 ZIP、ZipCrypto、结构不完整或 ZIP64 字段不一致的归档
- 忽略 `__MACOSX/`、`.DS_Store` 和 AppleDouble `._*` 等 macOS 辅助元数据，不把它们写入解压结果

每次解压先在最终目标同级创建仅当前用户可访问的隐藏 staging 目录。staging 根目录和其中的子目录固定为 `0700`，文件固定为 `0600`；不恢复归档声明的可执行位、setuid、setgid 或其他特殊权限。全部文件完成大小、CRC 和格式校验并同步后，才一次 rename 为最终目录，因此这些权限会保留到最终解压结果；失败、取消、目标抢占或碰撞都会删除 staging，且不会覆盖已有目录。

归档创建同样使用同级 `0700` 隐藏工作目录；单条目 payload 和中央目录临时文件固定为 `0600`。最终归档临时文件位于这个私有目录内，但使用进程 `umask` 决定的默认文件权限，原子移动或替换后作为用户保存的 ZIP 继续保留该权限。默认及 Finder 右键路径在目标已存在时失败；只有菜单栏系统保存面板已确认替换且目标是普通文件时，才在最终 ZIP 同步关闭后原子替换。目录和符号链接不会被替换，失败或取消时原文件保持不变。

## 密码

- 新密码至少 8 个字符；这里指最小长度，不是只能输入 8 位，也不限制为数字
- 建议使用 12 个以上字符，并混合字母、数字和符号；这是界面建议，不是额外的格式强制
- 密码不保存到 UserDefaults 或 Keychain
- 密码不传给外部命令，也不写入日志
- 用户选择复制自动密码时，剪贴板限制为当前 Mac，并附带 Concealed/Transient 隐私标记
- Swift `String` 无法提供可验证的内存归零保证；密码仅在当前操作的最小作用域内保留

## Finder 右键服务

- 服务仅声明给 `com.apple.finder`
- 只接收文件 URL，不接收文本、网页 URL 或脚本
- 不声明 `NSRestricted`，避免 Finder 右键操作前出现额外的系统“确认服务”弹窗
- Finder 传入文件后仍必须由用户在 aulycZip 密码框中确认创建；取消密码框不会写出文件
- 密码框显示所选项目名称和源文件目录，保存位置可使用源文件目录或用户另选的目录
- 输出文件名可以修改；输入只作为文件名处理，不能包含路径分隔符，省略 `.zip` 时会自动补齐
- 输出始终使用新的唯一文件名，不覆盖目标目录中已有的 ZIP
- 右键服务与菜单栏入口使用同一个 AES-256 创建流程

## 兼容性证据

自动化测试覆盖普通 ZIP、强制 ZIP64、AES-128/192/256 AE-1/AE-2、data descriptor、错误密码、内容篡改、输出限额、路径碰撞和事务回滚。CI 外部测试会让 7-Zip 解开 aulycZip 生成的普通/AES 归档及强制普通/AES ZIP64 归档，并让 aulycZip 反向解开 7-Zip AES ZIP；本地未配置 `AULYCZIP_7ZZ` 时测试明确显示 skipped。当前没有让 7-Zip 用小型夹具强制生成 ZIP64 的稳定接口，因此反向 ZIP64 由格式夹具和边界测试覆盖，不把它表述为 7-Zip 反向互操作证据。Keka 兼容声明仍需单独的人工或自动化证据。

## 在线升级

- 只接受中央 `dual-mirror-latest:2` 正式版清单及固定 GitHub、Gitee URL
- 两个来源都按相同顺序验证不可变 provenance 和安装包 SHA-256
- 安装前验证稳定版本、build、Commit、标签、Bundle ID、Team ID、最低系统版本和 arm64
- DMG 必须通过 Developer ID、Hardened Runtime、公证票据、staple 和 Gatekeeper 验证
- 只有当前进程来自 `/Applications/aulycZip.app` 时才允许准备替换
- 更新替换不会在压缩或解压任务进行时启动
- 替换任务等待当前进程退出，随后重新核对 staged App 的可执行文件哈希、Info.plist 哈希、签名、Team ID 和 Gatekeeper，再使用固定目标和可恢复备份；失败时恢复旧应用
- 所有校验子进程并发排空输出，具有超时、终止和输出上限
- 更新日志只记录不敏感的阶段和稳定错误码，不记录 URL 凭据、Token 或用户数据
